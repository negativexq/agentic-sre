# v0.2.0 real benchmark harness

The live benchmark is a sequential, single-agent trial. Each frozen fixture is
run in dataset order using the following control-plane path:

```text
fixture fault → real workload → telemetry → Prometheus rule
→ Alertmanager webhook → persistent Incident → investigation → cleanup
```

Fixture setup is benchmark-harness authority and is separate from the
investigation agent. The investigation registry remains read-only: it has no
shell, arbitrary query, Kubernetes mutation, or remediation operation.

Each trial starts from a healthy baseline, injects one bounded test fault,
stimulates the workload, and polls the real control plane for exactly one new
incident matching the fixture's symptom alert. Investigation starts before the
fault is cleaned up so current-state Kubernetes evidence is not lost. Cleanup
and recovery verification run in a `finally` lifecycle and a failed cleanup
aborts the next scenario.

The qualification command executes all ten fixture lifecycles and read-only
evidence preflights without an OpenAI call:

```bash
make benchmark-harness-check
```

Only a clean, freshly deployed environment that passes this zero-LLM
qualification may run `make benchmark-live`. The frozen live evaluation runs
each scenario once to bound paid API usage; variance estimation is deferred.
