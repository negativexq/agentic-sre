# v1.1.0 — Bounded Investigation Agent

v1.1.0 adds a bounded LangGraph investigation layer to the deterministic
Kubernetes RCA engine.

When deterministic resolution remains ambiguous, the investigator may select a
small number of allowlisted read-only observations. The model never determines
the root cause: observations are typed, normalized into deterministic evidence,
and passed through the existing hypothesis, verification, and resolution
pipeline.

## Highlights

- LangGraph `StateGraph` orchestration with explicit conditional routing.
- InformationGap-driven evidence acquisition.
- Strict gap, capability, and entity-target authorization.
- Read-only semantic tools for events, history, logs, neighbors, and describe.
- Typed observations and deterministic normalization.
- Investigation evidence overlays with deduplication and hypothesis rebuilding.
- Deterministic re-verification and re-resolution after every observation.
- Explicit turn, model, tool, per-gap, invalid-action, no-progress, and wall-time budgets.
- Duplicate-action protection and safe termination on repeated evidence or no progress.
- Checkpoint/resume support with an injectable checkpointer and in-memory default.
- Production-path coverage from a real `InMemorySource` through the default event tool, normalizer, case builder, and deterministic resolution.

## Trust boundary

The model decides where to look. The system decides what was observed. The
deterministic RCA engine decides what the evidence means. Verification decides
whether the evidence is sufficient, and resolution decides whether the root
cause is distinguishable.

The model cannot choose the root cause, set confidence or resolution, create
arbitrary findings, inspect unrelated entities, invoke unsupported tools, or
perform cluster writes. Invalid actions fail closed. `NO_DATA` and `UNKNOWN`
are not support for any hypothesis.

The deterministic diagnosis path remains the default. A clear `RESOLVED`
diagnosis performs zero model calls and zero tool calls. The investigator may
terminate with `AMBIGUOUS` or `INSUFFICIENT_EVIDENCE`; it never forces a result.

## Known limitations

- The default checkpoint is process-local and in-memory; checkpoint state is not yet a portable durable persistence format.
- Metrics and resource-pressure evidence are source-dependent.
- There is no distributed investigation ownership or durable Evidence/Hypothesis Ledger.
- Remediation remains proposal-only; there is no autonomous remediation.
- Real-model investigation value has not been established at scale.
