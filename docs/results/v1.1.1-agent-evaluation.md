## Bounded-agent run

The canonical configuration was fixed before execution:

- Provider: OpenAI Responses API
- Model: `gpt-5.6-luna`
- Budgets: 6 turns, 6 model calls, 8 tool calls, 2 tool calls per gap, 2
  invalid actions, 2 no-progress rounds, 120 seconds wall time.

Eligibility was computed from runtime state:

```text
resolution ∈ {AMBIGUOUS, INSUFFICIENT_EVIDENCE}
and a RESOLVABLE gap has a non-empty candidate_tools list
```

The seven eligible scenarios were:

```text
Scenario-14, Scenario-19, Scenario-25, Scenario-35,
Scenario-80, Scenario-81, Scenario-83
```

The other nine non-resolved scenarios were not investigable with the released
capabilities: `Scenario-18` and `Scenario-22` were AMBIGUOUS with no
resolvable gap; `Scenario-20`, `Scenario-24`, `Scenario-102`, and
`Scenario-105` were INSUFFICIENT_EVIDENCE with no resolvable gap. The remaining
12 incidents were already RESOLVED and correctly made zero model and tool
calls.

The run reached the model boundary on all seven eligible incidents. Each first
provider request returned `BadRequestError`; therefore no model action was
selected and no investigation tool executed. This is a completed
observational run, but it does not measure evidence-acquisition effectiveness.
It was not rerun.

## Scenario diagnostics

### Scenario-38

The published root-cause group is an HPA filter `*.*`. The canonical grader
does not produce an observable match for that filter, while the engine selects
`otel-demo/HorizontalPodAutoscaler/kafka`. This remains a benchmark-contract
issue; the official score is unchanged and no alias was added.

### Scenario-25

The v1.0.2 Top-3 included the Chaos `Schedule` as rank two. In v1.1.0 and
v1.1.1 the selected hypothesis has `StressChaos` as its causal actor and keeps
the `Schedule`, `StressChaos`, and recommendation `Pod` as one grouped
hypothesis. The Schedule therefore no longer appears as an independent Top-3
candidate. This is a causal-actor projection change from hypothesis grouping,
not a v1.1.1 checkpoint change; v1.1.1 made no investigation call for this
scenario because it was already RESOLVED.

## Conclusion

The checkpoint defect is fixed: the tagged run produced zero serialization
failures and reached the real provider boundary. The selected provider/model
request was rejected before action selection, so this evaluation cannot answer
whether bounded evidence acquisition improves RCA. The next useful work is to
establish a valid provider/model configuration or a separately approved model
evaluation; no RCA or agent tuning is justified by this run.
